## `03 / DATA QUALITY`

I don't see data quality as simply **finding errors**.

The real question is:

> **Why does bad data exist, how can we detect it, and how do we prevent it from coming back?**

### Quality dimensions

```text
                    DATA QUALITY
                         │
        ┌────────────────┼────────────────┐
        │                │                │
   COMPLETENESS      CONSISTENCY      CONFORMITY
        │                │                │
        └────────────────┼────────────────┘
                         │
             ┌───────────┴───────────┐
             │                       │
         ACCURACY               UNIQUENESS
```

I build rules and metrics around these dimensions to turn subjective statements like:

> "The data looks wrong."

into measurable statements like:

> **"3.7% of records violate the business rule."**
